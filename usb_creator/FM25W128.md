# FM25W128 support — Prism 1.0.1

The user reported that the Machinist board's SPI flash was not detected and supplied a chip photograph. The marking appears to be **FM25W128**. The 1.0.0 table did not contain its expected `A1 28 18` JEDEC ID. Existing `FM25Q128 / F8 32 18` entries are different Fidelix parts, not aliases for this Fudan device.

## Reviewed entry

```text
FM25W128,   0xA12818, 0x8000000, 0x1000, 0x20, 64, 0
```

In the documented Intel table format these fields mean: name, three-byte JEDEC ID, capacity **in bits**, erase size in bytes, erase opcode, FPT write granularity, and whether a separate Enable Write Status Register command is required.

| Parameter | Reviewed value |
|---|---|
| Manufacturer byte | `A1` (Fudan, non-prefix RDID form) |
| Device ID | `28 18` |
| Capacity | 128 Mbit = 16,777,216 bytes |
| Small erase unit | 4096 bytes, opcode `20` |
| Native program page | 256 bytes |
| FPT write granularity | 64 bytes, within an aligned 256-byte page |
| Status write policy | WREN, no separate EWSR `50` enable |

Primary evidence: [flashrom's Fudan chip implementation](https://github.com/flashrom/flashrom/blob/main/flashchips/fudan.c) and [JEDEC constants](https://github.com/flashrom/flashrom/blob/main/include/flashchips.h), checked on 14 November 2026. The implementation identifies a 16 MiB device, 256-byte page program, 4 KiB erase opcode `20` and `FEATURE_WRSR_WREN`. Its `TEST_OK_PROBE` flag establishes upstream probe evidence, not a write test of this Intel FPT integration. The manufacturer's [FM25W128 datasheet](https://www.fmsh.com/nvm/FM25W128_ds_eng.pdf) was discoverable but direct retrieval failed with HTTP 403/timeouts; it is not represented as independently read evidence.

## Implementation and retained checks

`flash_parts.py` appends this one exact row, preserves the existing table bytes, and rejects conflicting names, IDs, programming parameters, duplicate IDs, or malformed rows. Rebuilding from an already updated table is idempotent. The new table has 150 device rows and no DOS EOF control byte preceding the added row.

`build.py` applies this reviewed addition before regenerating the embedded `PARTS_HASH`, recompiling `PRISM.EXE`, and rehashing the packaged manifest. The original Intel `FPT.EXE`, four modified BIOSes, four factory references, and Secure Boot ownership are unchanged. No force-ID alias, unlock switch, relaxed hash check or fallback flash mode is introduced.

The existing USB update has **three paired files**: `PRISM.EXE`, `FPARTS.TXT`, `SOURCE.ZIP`. It contains no BIOS image and does not require USB repartitioning. Copy those three files to the existing Prism USB root and replace the old versions together. Keep `BIOS.BIN`, `FACTORY.BIN`, `BOARD.CFG`, boot files, backups and logs.

## Validation limits and target test

31 source tests pass, including four new part-table tests. The release report records the new table/menu/EXE hashes, portable checks and VM coverage. Software checks cannot prove that this board returns the expected JEDEC ID or grants SPI read/write access. Physical FM25W128 detection and flashing remain pending.

Boot the updated USB through Legacy/CSM and choose **1 — Backup entire 16 MiB** first. A successful backup must be exactly 16,777,216 bytes with SHA-256 recorded in `BACKUPS.TXT`. If detection still fails, preserve `FPTBACK.LOG` and `FLASH.LOG`; the exact error and observed chip ID are needed to distinguish a different RDID variant from another platform/access problem. A successful backup proves read access, not write permission. Full-chip write still requires the correct board/revision, typed `FLASH`, and complete readback verification.
